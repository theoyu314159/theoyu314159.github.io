2. Python 基礎語法與考題陷阱

2.1 快速輸入輸出 (Fast I/O)

在 APCS 實作題中，當測資筆數達到  $10^5$  級別時，傳統 input() 因包含過多的逐行開銷與 I/O 緩衝區處理，極易引發超時（Time Limit Exceeded, TLE）。競程標準實作必須改用 sys.stdin。

標準實作樣板 (Code Template)
import sys

def solve():
    # 方法 A：一次性讀取所有資料並以空白/換行分割（最推薦，適合資料量極大時）
    input_data = sys.stdin.read().split()
    if not input_data:
        return
    
    # 範例：第一個數字為 N，接續 N 個整數
    N = int(input_data[0])
    arr = [int(x) for x in input_data[1:N+1]]
    
    # 方法 B：逐行讀取（適合需要保留行結構的模擬題）
    # line = sys.stdin.readline().strip()

if __name__ == '__main__':
    solve()

  • 語法要點：  sys.stdin.read().split() 會自動將全數輸入按空白、Tab 與換行符號切割成串列，處理速度比 input() 快 3 到 5 倍。

  • 常見陷阱點：

  • 混用 input() 與 sys.stdin.read() 導致讀取指標錯位。

  • 使用 sys.stdin.readline() 時忘記加上 .strip()，保留了末尾的 \n，在字串比較時產生隱蔽 Bug。

2.2 串列 (List) 與字典 (Dict) 高頻操作

  • 語法要點：

  • 切片 (Slicing)：  arrstart:end:step。倒序切片 arr::-1 建立新串列。

  • 串列生成式 (List Comprehension)：  x * 2 for x in data if x % 2 == 0 比單純 for 迴圈更簡潔且執行速度更佳。

  • 字典/集合查表：  dict 與 set 底層基於 Hash Table 實現，內部查詢 x in my_set 平均時間複雜度為  $O(1)$ 。

  • 常見陷阱點：

  • 在迴圈中修改串列：  遍歷串列的同時執行 remove() 或 pop()，會導致串列索引即時重排，漏掉接續元素。

  • 時間複雜度誤判：  誤以為 x in list 的時間複雜度為  $O(1)$ （實際為  $O(N)$  線性搜尋）。在迴圈內執行 x in list 會直接將演算法惡化至  $O(N^2)$ 。快速查找務必先轉為 set 或 dict。

  • 未處理字典缺鍵：  直接存取 dictkey 引發 KeyError，應改用 dict.get(key, default)。

2.3 字串處理與二維陣列/矩陣模擬

  • 字串不可變性 (Immutability)：  Python 字串無法透過 s0 = ‘a’ 直接修改。頻繁變更字串應先轉為 List：s_list = list(s)，修改後再使用 “”.join(s_list) 合併，避免產生大量的暫存字串垃圾回收（GC）開銷。

  • 二維陣列初始化陷阱與矩陣旋轉樣板：

# ❌ 錯誤寫法：淺拷貝 (Shallow Copy) 陷阱！
# 這會讓 3 列完全指向記憶體中同一矩陣位址，修改 grid[0][0] 會導致所有列的第 0 格同時改變！
grid_wrong = [[0] * 4] * 3 

# ✅ 正確寫法：使用串列生成式獨立建立每一個 Row
rows, cols = 3, 4
grid = [[0] * cols for _ in range(rows)]

# 矩陣旋轉常用單行技巧 (觀念題與實作題高頻考點)
# 順時針旋轉 90 度：先上下翻轉 ([::-1]) 再轉置 (*zip)
grid_cw90 = [list(row) for row in zip(*grid[::-1])]

# 逆時針旋轉 90 度：先轉置 (*zip) 再上下翻轉 (註：或轉置後每行反轉)
grid_ccw90 = [list(row) for row in zip(*grid)][::-1]
  • 常見陷阱點：  走訪二維網格地圖（如上下左右移動 dr = -1, 1, 0, 0, dc = 0, 0, -1, 1）時，未先檢查邊界條件 0 <= nr < rows and 0 <= nc < cols 即存取 gridnr，引發 IndexError。
2.4 遞迴語法與時間複雜度 ( $Big-O$ )

  • 語法要點：  遞迴函式必須具備「終止條件 (Base Case)」與「遞迴推展 (Recursive Step)」。

  • 常用  $Big-O$  複雜度評估：

  • $O(1)$ ：常數時間（如 Hash Table 存取、陣列索引讀取）。

  • $O(\log N)$ ：二分搜尋法。

  • $O(N)$ ：單層迴圈走訪。

  • $O(N \log N)$ ：高效排序算法（如 Python 内建 Timsort .sort()）。

  • $O(N^2)$ ：雙層巢狀迴圈（如簡單模擬、暴搜所有數對）。

  • $O(2^N)$ ：未進行記憶化的指數級遞迴（如樹狀分支探勘）。

  • 常見陷阱點：  Python 預設最大遞迴深度為 1000。若實作 DFS 深度過深，會引發 RecursionError。競程中可用 sys.setrecursionlimit(200000) 提高限制。

3. 觀念題語法追蹤與解題技巧 (Code Tracing)

3.1 手動追蹤 (Code Tracing) 步驟拆解

APCS 觀念題考驗的是「人肉編譯器」的精密程度。請嚴格執行以下三步驟：

  1. 標示控制區塊：  用筆圈出 for / while 的起止條件與 if/else 的分支走向。

  2. 建立變數狀態追蹤表（Variable State Table）：  欄位需包含「執行行號」、「主控制變數」、「陣列/變數狀態」與「條件判斷結果（True/False）」。

  3. 單步模擬：  變數每變更一次，立刻劃掉舊值更新為新值。

APCS 風格實戰追蹤範例

追蹤以下程式碼片段之輸出結果：

line 1: arr = [4, 1, 3]
line 2: total = 0
line 3: for i in range(len(arr)):
line 4:     if arr[i] % 2 != 0:
line 5:         total += arr[i] * i
line 6:     else:
line 7:         total -= arr[i]
line 8: print(total)
變數狀態追蹤表 (Variable State Table)

步驟 (Step),行號 (Line),迴圈 i,陣列 arri,條件判斷 arri % 2 != 0,變數 total 變更過程,說明 / 輸出

1,1-2,-,-,-,0,初始狀態：total = 0

2,3-4,0,4,False (4%2==0),0 - 4 = -4,走 else 支線 (Line 7)

3,3-4,1,1,True (1%2!=0),-4 + (1 * 1) = -3,走 if 支線 (Line 5)

4,3-4,2,3,True (3%2!=0),-3 + (3 * 2) = 3,走 if 支線 (Line 5)

5,8,-,-,-,3,迴圈結束，印出  3

3.2 變數作用域 (Variable Scope) 陷阱

  • 全域 (Global) 與區域 (Local) 覆蓋：  在函式內部若對變數進行賦值（如 x = 5），Python 會自動將 x 宣告為該函式的區域變數。若未預先宣告 global x 卻在賦值前讀取它，會引發 UnboundLocalError。

  • 物件傳遞機制 (Pass-by-assignment)：

  • 不可變物件 (Immutable)：  整數、字串、Tuple。傳入函式內修改時會建立新物件，不影響外部變數。

  • 可變物件 (Mutable)：  List、Dict。傳入函式內若透過 arr.append() 或 arr0 = k 修改， 會直接變更外部原始物件的內容 ！

3.3 遞迴呼叫堆疊 (Call Stack) 與邊界條件

觀念題常考遞迴呼叫順序與回傳值的累加過程。必須在草稿紙上繪製 Call Stack 的  Push（壓入）與 Pop（彈出）  歷程。

範例程式碼
def f(n):
    if n <= 1:
        return 1
    return n + f(n - 2)

print(f(3))
Call Stack 執行歷程拆解 (ASCII 堆疊演示)
【階段一：遞迴向下壓入 (Push)】
1. 呼叫 f(3)：
   - 非 Base Case (3 > 1)
   - 需計算 3 + f(1)，暫停並壓入 Stack
   
2. 呼叫 f(1)：
   - 觸發 Base Case (1 <= 1)
   - 準備回傳 1

Stack 狀態 (由頂至底):
|  f(1)  | -> 抵達 Base Case，開始 Pop
|  f(3)  | -> 等待 f(1) 的結果 (3 + f(1))
+--------+

【階段二：觸發 Base Case 向上彈出 (Pop)】
1. f(1) 回傳 1 彈出 Stack。
2. 回到 f(3)：計算 3 + 1 = 4，回傳 4 並彈出 Stack。
3. 最終 print(4) 輸出結果為 4。

4.2 雙指標 (Two Pointers) 與 貪婪演算法 (Greedy)

  1. 解題核心觀念：

  2. 雙指標：  利用左右指標 L, R 從陣列兩端向中間逼近（或快慢指標），將  $O(N^2)$  的列舉優化至  $O(N)$ 。

4.3 二分搜尋法 (Binary Search)

  • 解題核心觀念：  在具備「單調性（Monotonicity）」的單維資料或答案空間中，每次將搜尋範圍縮減一半。對於極值優化問題，採用「答案二分法（Binary Search on Answer）」。

  • 適用題型特徵：  已排序資料查找、求「滿足條件的最大最小值 / 最小最大值」（如切木頭、基地台覆蓋）。

答案二分法標準實作樣板 (Code Template)
def check(mid, data, K):
    # 驗證當前答案 mid 是否合法（根據題目條件撰寫 $O(N)$ 檢查邏輯）
    count = 0
    # ... 檢查邏輯 ...
    return count <= K

def binary_search_on_answer(data, K):
    low = 1                  # 搜尋下界
    high = max(data)         # 搜尋上界
    ans = high
    
    while low <= high:
        mid = (low + high) // 2
        if check(mid, data, K):
            ans = mid        # 當前 mid 可行，記錄答案並嘗試找更小/更大值
            high = mid - 1   # 縮減搜尋範圍
        else:
            low = mid + 1
            
    return ans

  1. 關鍵邏輯步驟：

  2. 確定答案可能開區間 low, high。

  3. 撰寫單調性驗證函式 check(mid)。

  4. 執行 while low <= high 迴圈收斂邊界。

4.4 基礎搜尋與圖論 (DFS 與 BFS)

  • 解題核心觀念：

  • DFS (深度優先搜尋)：  沿路徑深入探勘，配合回溯（Backtracking）尋找所有可能解或連通塊。

  • BFS (廣度優先搜尋)：  利用佇列（Queue）由近至遠逐層擴展，保證首次到達目標點時為 最短路徑 。

  • 適用題型特徵：  網格地圖探勘（島嶼數量）、迷宮離去最短步數、圖形連通性分析。

網格地圖 BFS 標準實作樣板 (Code Template)
from collections import deque

def bfs_grid(grid, start_r, start_c):
    rows, cols = len(grid), len(grid[0])
    queue = deque([(start_r, start_c, 0)])  # (r, c, dist)
    visited = set([(start_r, start_c)])
    
    # 上下左右四方向向量
    dr = [-1, 1, 0, 0]
    dc = [0, 0, -1, 1]
    
    while queue:
        r, c, dist = queue.popleft()
        
        # 抵達終點條件判斷（假設右下角為終點）
        if r == rows - 1 and c == cols - 1:
            return dist
            
        for i in range(4):
            nr, nc = r + dr[i], c + dc[i]
            # 邊界檢查與障礙物/已存取判斷
            if 0 <= nr < rows and 0 <= nc < cols:
                if grid[nr][nc] != 1 and (nr, nc) not in visited:  # 1 代表牆壁
                    visited.add((nr, nc))
                    queue.append((nr, nc, dist + 1))
                    
    return -1  # 無法到達

考試當天實戰應試心法
觀念題戰術（測驗時間：60 分鐘）

  1. 時間嚴格控管：  共 25 題，每題平均分配  2.4 分鐘 。前 15 題語法與簡單追蹤需迅速拿下，保留時間給後段複雜遞迴題。

  2. 落實白紙模擬：  遇到遞迴呼叫必畫 Call Stack 堆疊圖（標註 Push/Pop），遇到迴圈變數必畫「變數狀態追蹤表」。 切忌憑感覺心算！

  3. 選項極端值排除法：  觀察選項邊界（如 0, N-1, -1），將極端狀況帶入程式碼，快速排除不合邏輯的干擾選項。

實作題戰術（測驗時間：150 分鐘）

  • 審題與  $Big-O$  倒推解法（前 5 分鐘）：

  • Python 在 APCS 時限通常為 1.0 秒，可執行約  $10^8$  次基本運算。

  • 若測資規模  $N \le 1000$ ，允許  $O(N^2)$  解法（雙重迴圈）；若  $N \le 10^5$ ，則必須設計  $O(N)$  或  $O(N \log N)$  演算法。

  • 記憶體限制通常為 256MB，二維陣列大小不宜超過  $5000 \times 5000$ 。

  • 子任務 (Subtask) 搶分策略（關鍵拿分技巧）：

  • 若看到第三題或第四題無法立刻想到最優解（如  $O(N \log N)$  的二分搜或 DP）， 切勿卡關或留白！

  • 優先寫出  $O(N^2)$  或  $O(2^N)$  的暴力搜尋（Brute Force）程式碼，確保穩穩吃下 Subtask 第一子任務的 40%~60% 配分。拿滿基本分後，再嘗試優化至滿分。

  • 離線自我測試與邊界檢查（交卷前 10 分鐘）：

  • 檢查極端測資：N = 1、空輸入、全為負數、陣列元素重複等狀況。

  • 確認二維陣列走訪時，索引是否會發生 IndexError（驗證 0 <= r < rows and 0 <= c < cols）。

  • 確認全域變數是否在多筆測資間正確重置。
